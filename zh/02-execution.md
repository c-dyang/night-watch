# 执行卷：外部独立 LLM、小片段审计与会话防飘

> 记忆卷管"该知道的到达"，本卷管"正在做的事别飘"。
> 核心一句话：**执行期的自律不可信，所以判定要搬到会话之外，看小片段，顺手把经验精炼评级。**

> ⚠️ 本卷六条不变量：**四条在持续运行且可追溯（`Q1`）** —— 外部判定、原始片段输入、后置纠偏、证据只取生产会话；**另两条为 `Q2`（有事件、未系统留痕）** —— 两档延迟、预检不退化为审批。
> **一条 `Q0`（受控量化）都没有，也没有一条 `Q3`（纯推理）**。
> 请按「六条都是实际堆出来的、但收益尚未量化」阅读，而不是按「设计推理」或「已证实」阅读。见 `07-sources.md` §2 / §4。

## 1. 为什么判定必须在会话之外

### 1.1 自审为什么不可信

三个理由，从强到弱：

| 理由 | 说明 | 后果 |
|---|---|---|
| **上下文即立场** | 同一上下文里，模型对自己刚做的选择有"承诺一致性"压力，倾向于为它找理由 | 越权被解释成"合理变通"，遗漏被解释成"不需要" |
| **整理权即遮蔽权** | 若由执行方决定"给审计看什么"，它能交出一份体面的摘要 | 审计通过率接近 100%，且**通过得毫无信息量** |
| **贵模型不能高频自检** | 判定要每轮跑、要可回归；用主模型自检等于把最贵的算力做成常态开销 | 判定频率被成本压到"只在出事后看一次" [INV-X4] |

第一、二条合起来是本卷的根：**判定必须来自会话之外，且输入必须是原始片段** —— 这是两条独立的不变量 [INV-E1] [INV-E2]。

### 1.2 三个隔离

| 隔离 | 具体含义 | 少了会怎样 |
|---|---|---|
| **进程隔离** | 判定跑在独立进程/独立调用里，不共享主会话的上下文 | 判定被主会话的既有推理污染 |
| **提示隔离** | 判定提示自包含（角色、判据、输出格式全在提示里），拷出去就能跑 | 提示依赖会话历史 ⇒ 不可复现、不可回归 |
| **账本隔离** | 判定结果写入独立账本，只有外部侧能改分 | 执行侧能改分 ⇒ 写评合一，账本失效 [INV-M9] |

### 1.3 判定的权限边界

> **外部判定只说"这一步有问题"，不说"你该怎么改"。**

这不是谨慎，是防"双指挥"。一旦判定方开始下指令，执行方就有两个上级，冲突时的默认行为是**挑一个更省事的服从** —— 而省事的那个通常是不改。判定的输出止于**类别 + 锚点 + 理由 + 严重度**，改法留给执行方或留给人。

### 1.4 成本结构

判定的成本必须满足两条，否则它会自然衰减成"事后抽查"：

1. **每次调用廉价**：用免费/本地模型；单次判定 = 一个片段 + 一份固定判据，输出短。
2. **每轮次数恒定**：判定次数只与**片段数**有关，与会话长度无关 —— 这是"小片段"设计的经济学理由，不是精度理由。

## 2. 审计小片段

### 2.1 片段是什么

一个片段不是"最近 N 轮对话"，而是**三联**：

```
意图（用户/任务要什么） → 动作（实际做了什么：工具调用、写文件、发消息） → 结果（工具返回、产物、退出码）
```

只给"对话"会导致判定奖励措辞；只给"动作"会丢掉意图，无法判越权。三联缺一，判定就应该返回"无法判定"而不是"通过"。

### 2.2 为什么是小片段

| 维度 | 小片段 | 整会话 |
|---|---|---|
| 定位精度 | 能指到**具体轮次与具体动作** | 只能说"整体感觉有风险" |
| 成本 | 线性、可预算、可批量 | 随长度超线性 |
| 可回归 | 同一片段重跑应得同一档结论 | 每次上下文不同，结论随机 |
| 抗污染 | 不受后期推理影响 | 后文会"合理化"前文 |

### 2.3 三类判据

| 类 | 问题 | 典型证据 | 严重度 |
|---|---|---|---|
| **越权**（overreach） | 做了没被授权的事 | 动作落在白名单外 / 敏感面未确认 | 高，可即时拦 |
| **遗漏**（omission） | 承诺了没做，或该验证没验证 | 说了"已改"但无产物 / 无退出码 | 中高，入账并纠偏 |
| **失序**（disorder） | 跳过必须步骤 | 先清空后沉淀 / 未备份即改配置 | 中，入账 |

严重度决定走哪档延迟（见 2.5）。**判据本身要可枚举**：这三类能枚举，所以适合前置判据；而"这个回答好不好"不能枚举，就不该做前置判定 [INV-E3]。

### 2.4 判定记录（结构化输出）

```json
{
  "snippet_id": "<会话/轮次定位>",
  "class": "ok | overreach | omission | disorder | undecidable",
  "severity": "low | medium | high",
  "anchor": "<证据在片段中的位置：第几轮、哪个动作、哪个字段>",
  "reason": "<一句话，必须能被另一个人复核>",
  "score": 0,
  "judge": "<模型/规则标识>",
  "created_at": "<ISO 时间>"
}
```

硬规则三条：

- `class=ok` 不需要理由；**其他任何一类没有 `reason` 即视为无效判定**（不写"通过"，写"无效"）。
- `anchor` 必须能回到原始片段，回不去就是编的。
- `score` 只能由外部侧填（这里只占位）；执行侧提交时留空。

### 2.5 两档延迟

| 档 | 触发 | 延迟 | 权限 |
|---|---|---|---|
| **即时纠偏** | 仅 `overreach` 且 `severity=high` | **≤1 轮**，同步返回 | 可以拦（拒绝执行 / 要求确认） |
| **异步入账** | 其余全部 | 分钟到小时 | 只能记，不能拦 |

设计意图：**同步通道越窄越好**。同步判定会拖慢主链路，而主链路一旦变慢，最省事的优化就是把审计关掉 [INV-E5]。所以只有"会造成不可逆损害"的那一类才允许阻塞。

## 3. 经验预检 ＝ 会话防飘

### 3.1 飘的三种形态

| 形态 | 表现 | 判据 |
|---|---|---|
| **目标漂移** | 做着做着偏离原始要求，且不自知 | 动作与原要求的关键词/对象不再对应 |
| **口径漂移** | 同一个数字/路径/结论每次说法不同 | 同一实体多次出现，值不一致 |
| **权限漂移** | 动作面逐步扩大（先只读，后来改配置） | 动作分类等级单调上升 |

三种漂移的共同点：**单轮都合理，连起来才偏**。这就是为什么必须由外部按片段序列看，而不是由内部按当轮感觉看。

### 3.2 预检的时机与成本闸门

预检不是每轮跑，只在**动作分级命中**时跑：

| 动作等级 | 例子 | 预检 |
|---|---|---|
| 只读 | 读文件、检索、查询 | 不跑（0 成本） |
| 可逆写 | 写产物文件、生成报告 | 轻量：命中经验条目即提示 |
| 不可逆/敏感 | 删改配置、发消息、动凭据、重启服务 | 必跑：命中条目 + 风险 + 反例 |

**这条分级本身是不花钱的**（按动作分类查表），所以"预检存在"不等于"预检烧钱"。

### 3.3 预检输出什么

预检的输出是**提示**，不是**许可**：

```
命中条目：EXP-00xx（相关经验/陷阱）
风险：<一句话>
反例：<上次类似动作出了什么事>
建议：<可选，执行方可以不采纳>
```

三条纪律：

- **不阻断**：只有 `overreach` 才拦，预检只提示 [INV-E6]。
- **给反例优先于给规则**：反例可判断是否适用，规则只能照做或不做。
- **命中不到就说命中不到**：不许为了显得有用而编一条"注意谨慎"。

### 3.4 后置纠偏优先于前置路由

这是本卷最容易引起争议的一条，值得写清：

> **开放域不做前置分类，纠偏放在动作之后。**

| 做法 | 问题 |
|---|---|
| 前置路由（先判断"这是哪类任务"，再分派） | 类不可枚举 ⇒ 规则爆炸；新情况先被拦 ⇒ **压制探索**；规则过期后成为毒药（拦的正是现在该做的） |
| **后置纠偏**（先做，按片段判定，错了就纠） | 代价是偶尔做错一次；收益是**新情况不被拦**，且规则由真实失败长出来 |

**可枚举的域例外**：像"文件后缀 → 处理工具"这种事，枚举是闭合的、失败代价低，前置路由反而是对的。判断标准不是"前后"，而是**类是否可枚举、失败是否可逆**。

### 3.5 防飘的三条硬动作

1. **动作前回看原始要求一句话**：把最初的要求原文取出来（不是记忆里的转述），对齐一次。
2. **数值与路径从工具取，不从记忆取**：任何 IP、端口、行数、时间戳都必须现场取，禁止"我记得是…"（这条同时降低口径漂移与幻觉）。
3. **越权即拦，不越权不拦**：拦的理由只能落在"白名单外/未确认的敏感面"上，不能落在"我觉得没必要"上。

## 4. 顺带产出：经验精炼与评级

执行域是唯一能产出**真实证据**的地方，所以经验精炼与评级顺手在这里做，而不是让记忆域"凭印象写经验"。

### 4.1 流水（五步，顺序固定）

```mermaid
flowchart LR
  A["会话片段（三联）"] --> B["候选条目<br/>现象 / 根因 / 判据"]
  B --> C["证据锚点<br/>指到轮次与动作"]
  C --> D["夜间沉淀入库<br/>正文 + 账本占位"]
  D --> E["外部盲审改分<br/>±1/±2/±3"]
  E --> F["检索可见<br/>按分数排序"]
```

### 4.2 评级只来自生产会话

> **一条经验的分数，其唯一合法证据来源是生产环境里的会话片段。** [INV-E4]

三个"不算证据"的东西：

- 模型自述（"我认为这样更稳妥"）—— 无锚点，不可复核。
- 文档转述（"官方文档说…"）—— 是外部信息，不是本系统的运行事实。
- 别人的经验（"一般来说…"）—— 可以入库为 `claimed` 档，但不能因此拿高分。

推论：**"写得好"不该换来分数**。若账本奖励的是表达力，最终会得到一份漂亮但没用的经验库。

### 4.3 分工

| 角色 | 只做 | 绝不做 |
|---|---|---|
| 执行侧（干活的那个会话） | 提交片段、写候选条目、附证据锚点 | 给自己的条目打分、修改账本 |
| 外部盲审（独立进程里的廉价模型） | 看原始片段与条目，给分数与理由 | 改正文、改判据、给执行下指令 |
| 人 | 一票否决、改优先级、决定是否发布 | —— |
| 夜间链 | 整体重建派生索引、按规则墓碑化 | 改分数、改正文结论 |

### 4.4 分数怎么用（而不是怎么打）

分数只有三个用途，其余都不该拿它做决策：

1. **排序**：检索时同主题条目按分数排序，让高可信的先到。
2. **提示强度**：高分条目可以进注入层摘要，低分只进检索层。
3. **淘汰**：连续低分 → 墓碑。

**不该做的**：用分数决定"能不能执行"（分数是可信度，不是许可）；用分数做跨主题比较（不同主题的分数不可比）。

## 5. 最小契约

### 5.1 三份结构化产物

| 产物 | 写入者 | 结构要点 |
|---|---|---|
| 片段包 | 执行侧（每轮/每动作） | `intent / actions[] / outcomes[]`，全部原始（不经摘要） |
| 判定记录 | 外部侧 | 见 2.4 的 JSON；`class` 非 ok 时 `reason` 必填 |
| 候选条目 | 执行侧 | `title / type / evidence[anchor, strength]`，**无 `confidence` 字段**（分数由外部侧填） |

第三行那个"无字段"是设计：**提交格式里根本没有分数位，执行侧就无法自评** —— 用格式而不是纪律来保证不变量，比写十条注意事项可靠。

### 5.2 三条可测判据

1. **可复现**：同一片段重跑判定，`class` 与 `severity` 应同档（允许 `reason` 措辞不同）。不一致率 >20% ⇒ 判据模糊，回去改提示。
2. **可定位**：随机抽 20 条判定，`anchor` 全部能回到原始片段。有回不去的 ⇒ 在编。
3. **不阻塞**：统计同步通道的占比与耗时；若同步判定平均耗时超过一次普通工具调用，说明该降级到异步 [INV-E5]。

## 6. 本卷失效模式（诚实清单）

| 失效 | 症状 | 结构原因 |
|---|---|---|
| 审计退化成盖章 | 通过率≈100%，且从未拦下任何东西 | 输入被整理过 / 判定在同一上下文 [INV-E1/E2] |
| 预检变审批 | 每个动作都在等确认，无人值守名存实亡 | 预检拿到了阻断权 [INV-E6] |
| 规则成毒药 | 明明该做的事被一条老规则拦住 | 前置路由 + 规则无 TTL |
| 账本奖励表达力 | 分高的条目总是写得漂亮的那几条 | 评级证据不是生产片段 [INV-E4] |
| 判定太贵被关掉 | 一开始有审计，两周后没了 | 判定没有走"免费模型 + 恒定次数" |
| 双指挥 | 执行方在两个上级之间挑省事的服从 | 判定方越界下指令 |

## 7. 从零搭最小版本（顺序不能换）

1. **先只做一件事**：把每个动作记成三联片段（意图/动作/结果），落盘。**此时还没有判定**。
2. 接一个**独立进程**的判定调用，只判 `overreach` 一类，只输出 `ok / overreach / undecidable` 三值。
3. 加**异步账本**：判定一律先入账，不阻塞任何动作。
4. 只有 `overreach` 一条同步通道，且限 `severity=high`。
5. 加**预检**：只对"不可逆/敏感"动作跑，输出提示不输出许可。
6. 最后加**候选条目与盲审改分**，并把"无 `confidence` 字段"写进提交格式。

第 1 步做完就已经能回答"这次到底干了什么"；第 4 步才谈得上防事故；第 6 步才是经验闭环。**先做第 6 步的人会得到一堆没人信的分数。**
