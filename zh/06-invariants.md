## 一、记忆域（INV-M）· Memory

| 编号 | 不变量 | 反推来源 | 违反后的症状 | 强度 |
|---|---|---|---|---|
| INV-M1 | **注入地图，不注入内容**：每轮只给索引、摘要与检索指令 | 直接注入正文 ⇒ 上下文被内容占满，且"给了结论就不再检索" | 新人（或新会话）以为知道，实际用的是过期摘要 | 实测 |
| INV-M2 | **检索下钻不可跳层**：注入层 → 索引层 → 蒸馏层 → 原始流 | 直接翻原始流，约 99% 是工具噪音，且拿最脏的一层做判断 | 判断建立在单次失败片段上，结论反复翻烧饼 | 观察 |
| INV-M3 | **单一事实源 + 派生产物**：派生索引禁止手改，只由重建生成 | 手改索引与正文不同步 | 检索命中与正文矛盾，且无法判断哪边旧 | 实测 |
| INV-M4 | **沉淀必须先于清空**：先落盘、后日切 | 清空与沉淀顺序可交换的假设 | 未沉淀的内容真的消失，且**不会报错** | 主张 |
| INV-M5 | **派生索引整体重建，不做增量** | 增量更新在条目删改后留下悬挂项 | 索引缓慢漂移，越用越不准 | 实测 |
| INV-M6 | **缺一层报一层，失败不重跑** | 失败自动重跑 ⇒ 缺口被"补齐的假象"掩盖 | 链条断一环但日报全绿 | 实测 |
| INV-M7 | **经验条目必须可被否定**：置信度账本 + 墓碑淘汰，负分必填理由 | 只增不减的经验库 | 错误经验永久驻留，且越旧越像权威 | 实测 |
| INV-M8 | **盲审清单不带置信度标记，也不带作者自评** | 打分受既有分数与自述影响（光环效应） | 高分条目永远是高分，新条目永不上位 | 主张 |
| INV-M9 | **写与评分离**：执行侧只写条目与证据，外部侧只改置信度 | 同一侧既写又评 | 自评膨胀，账本失去区分度 | 实测 |
| INV-M10 | **快慢分档**：快信号（越权/遗漏）≤1 轮纠偏；慢信号（置信度）周/月生效 | 用同一节奏处理两种信号 | 要么纠偏太慢，要么账本抖动 | 主张 |
| INV-M11 | **正文禁全文读**：任何单一事实源只按章节定位读取 | 体量增长后仍全文读 | 上下文预算被单一文件吃掉 | 实测 |

## 二、执行域（INV-E）· Execution

| 编号 | 不变量 | 反推来源 | 违反后的症状 | 强度 |
|---|---|---|---|---|
| INV-E1 | **判定必须来自外部独立 LLM**：独立进程、独立提示、独立账本 | 同一上下文自审，会为既有选择辩护 | 审计永远通过，等于没有审计 | 主张 |
| INV-E2 | **审计输入是原始片段**，不经被审模型摘要或转述 | 让被审方自己整理"给它看的东西" | 审计看到的是美化版，越权与遗漏被抹平 | 主张 |
| INV-E3 | **后置纠偏优先于前置路由**：开放域不做前置分类 | 前置分类不可枚举 ⇒ 规则爆炸、压制探索、过期规则变毒药 | 规则越写越多，新情况一律被拦 | 主张 |
| INV-E4 | **评级的证据只来自生产环境会话**：不接受模型自述、不接受文档转述 | 用"写得好不好"代替"做没做过" | 账本奖励会写的人，不奖励做对的事 | 主张 |
| INV-E5 | **两档延迟**：即时纠偏 ≤1 轮；超时的判定只入账、不追责 | 所有判定都走同步 | 主链路被审计拖慢，自动降级成"不审" | 主张 |
| INV-E6 | **预检不得退化为审批**：预检输出"提示 + 风险"，不输出"阻断一切" | 任何动作都要过闸门 | 无人值守系统卡在等确认 | 主张 |

## 三、设备域（INV-D）· Device

| 编号 | 不变量 | 反推来源 | 违反后的症状 | 强度 |
|---|---|---|---|---|
| INV-D1 | **判活看产物，不看进程、不看面板** | 进程在 ≠ 功能在 | 进程活着但服务已死，绿灯照常 | 实测 |
| INV-D2 | **健康结论只能取自链末端产物** | 观测点写在链条中段 | 后半段被杀，面板仍显示绿 | 实测 |
| INV-D3 | **不被调度器观测的执行体必须自报结果** | 经隐藏窗口启动器拉起的脚本退出码恒 0 | 调度器永远看不到失败 | 实测 |
| INV-D4 | **0 成本闸门先于一切 LLM**：信号先过确定性判据，再决定是否唤醒 | 每个信号都过一次模型 | 成本随噪音线性上涨，判定被做穷 | 实测＋主张 |
| INV-D5 | **唤醒而非轮询**：成本随事件发生，不随时间流逝 | 固定间隔轮询 | 平静期也照付，异常期又不够快 | 主张 |
| INV-D6 | **执行面极窄**：能自动修的只有幂等动作，其余一律提级 | 自愈动作不幂等 | 越修越坏，且两次修复互相覆盖 | 实测 |
| INV-D7 | **抑制粒度 ≥ 一个可独立失败的单位，且带 TTL、可回溯** | 按粗粒度抑制 | 一次抑制把同类真实失败一起盲掉整个 TTL | 实测 |
| INV-D8 | **判断与投递分离**：执行者只写队列，由有记忆的一侧负责投递（含时段与去重） | 执行者直接找人 | 重复轰炸、安静时段被打扰、丢消息 | 实测 |
| INV-D9 | **去噪三层，不加第四层**：任务级记忆 → 抑制表（TTL）→ 时间窗去重 | 每遇一次误报就加一层 | 去噪逻辑自身变成最复杂的模块 | 主张 |
| INV-D10 | **辅助会话惰性创建**：缺席不是故障证据 | 把"没有会话"当成"巡检没跑" | 每次误判都触发一次无意义处置 | 实测 |

## 四、跨域（INV-X）· Cross-cutting

| 编号 | 不变量 | 反推来源 | 违反后的症状 | 强度 |
|---|---|---|---|---|
| INV-X1 | **监督者与被监督者的写入权分离**：审计行不能由被监督的任务自己写 | 任务自己追加判活行 | 它失败时，判活线自身失明 | 实测 |
| INV-X2 | **模块之间只靠约定文件耦合，不靠调用** | 模块间直接 API 调用 | 任一方换实现都要改另一方 | 实测 |
| INV-X3 | **会话是缓存，文件是真相**：全部会话可日切，含主会话 | 把会话当存储 | 清空即丢记忆 | 实测 |
| INV-X4 | **判定用免费/本地模型，生成用便宜模型** | 用贵模型做判定 | 成本不可预测，判定频率被迫降低 | 实测 |
| INV-X5 | **静默失败必须可与静默成功区分** | "无输出即正常"的默认假设 | 失败长期无人知晓，事故以"一直好好的"开场 | 实测 |

## 五、依赖关系（违反一条会连带违反谁）

```
INV-X3 ──► INV-M4 ──► INV-M6          （会话能日切，才要求沉淀先于清空；沉淀有缺口才要求报缺口）
INV-X1 ──► INV-D1 / INV-D2            （写入权不分离，判活与末端取数都不可信）
INV-X1 ──► INV-M9                     （写评不分离，账本失去区分度）
INV-D4 ──► INV-X4 ──► INV-E1          （闸门省钱，才养得起常驻外部判定）
INV-M7 ──► INV-E4 ──► INV-M8          （条目可否定，评级才需要真实证据；证据可信才谈得上盲审）
INV-X5 ──► INV-D3                     （要求失败可见，才要求执行体自报结果）
```

**读法**：箭头左侧被违反时，右侧的不变量"形式上还成立、实际上已失效"。这也是为什么失效模式必须单独成套（主文档 §5 ＋ 三卷各一节）—— **这类失效不报错**。

## 六、变更规则

1. 新增不变量必须写清"反推来源"；写不出来说明它是偏好，不是不变量 → 移到术语或附录。
2. 删除不变量必须同步删除正文对它的引用，否则引用断链。
3. `[主张]` 条目被实测证实后改标 `实测`；被证伪则整条重写，**不许悄悄降级为措辞**。
4. 编号一旦发布不改（避免外部引用错位）；废弃条目保留编号，标注 `DEPRECATED` 并指向替代条目。
