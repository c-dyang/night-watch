# 附录 A：参考实现清单

> 本附录给"想照着搭"的人一个体量与边界的概念。**行数只是量级，不是承诺**；换语言、换宿主、换存储都会变。判断能不能用，看不变量，不看行数。

- 代码许可：**MIT**（正文与本附录其余部分为 CC BY 4.0）
- 总量级：**约 3.0k 行**，分布在 8 个互不调用的子系统

---

## A.1 子系统与体量

| # | 子系统 | 行数量级 | 职责 | 对应不变量 |
|---|---|---|---|---|
| 1 | 会话工厂 | ~400 | 建会话、收养已有会话、注入开场内容、归档旧会话 | INV-X3 / INV-M4 |
| 2 | 工具网关 | ~250 | 一张路由表 = 能力清单；按表分发；调用落审计 | INV-X2 / INV-E6 |
| 3 | 全文检索（中文） | ~650 | 双字切分 + 索引整体重建 + 按日期窗检索 | INV-M2 / INV-M3 / INV-M5 |
| 4 | 结果上报与调度兜底 | ~200 | 执行体自报退出码；调度器侧的兜底与超时救援 | INV-D3 / INV-X1 |
| 5 | 闸门与提级通道 | ~800 | 三态闸门、抑制表、队列、投递规则 | INV-D4 / D7 / D8 |
| 6 | 夜间链编排 | ~300 | 三段串联、缺口上报、不重跑 | INV-M6 |
| 7 | 索引重建 | ~250 | 从正文整体重建派生索引与题库 | INV-M3 / INV-M5 |
| 8 | 判定客户端 | ~200 | 独立进程调用外部模型、解析结构化输出、入账 | INV-E1 / INV-E2 / INV-E5 |

**读法**：1–3 是记忆，4–5 是设备，6–8 是跨域粘合。没有"核心大模块"，每个都能单独扔掉重写。

## A.2 每个子系统的最小接口（语言无关，只给形状）

### 1 会话工厂

```
create(date_key) -> session        # 建一个新会话，注入开场内容
adopt(session, handover_text)      # 收养并注入昨日沉淀
archive(session) -> artefact_path  # 归档为压缩产物
```

约束：`create` 必须幂等（同一天重复调用返回既有会话，不重建）。

### 2 工具网关

```
dispatch(action_name, params) -> {rc, stdout, artefacts[]}
list() -> [{module, func, desc, disabled}]
```

约束：`dispatch` 只认表里的名字；表外一律 rc 非 0 且**不执行**。调用一律落一行审计。

### 3 全文检索（中文）

```
index_rebuild(source_files) -> {docs, terms}
search(query, date_from, date_to, limit) -> [{doc, snippet, score}]
```

约束：`index_rebuild` 必须能从头重建（不与旧索引合并）；中文必须双字切分或分词，**不要指望默认分词器**。

### 4 结果上报与调度兜底

```
report(source, rc, note)           # 执行体自己调用
watch(task_name) -> {last_result, last_run}
```

约束：`report` 的写入者必须是执行体；`watch` 读到的 `last_result` 在经包装器启动时不可信，需配兜底（超时救援 / 哨兵产物）。

### 5 闸门与提级通道

```
gate(signal) -> {state: drop|defer|wake, reason}
enqueue(event)                     # 只追加
deliver(queue) -> {sent[], skipped[]}   # 安静时段、去重、上限
```

约束：`gate` 纯函数无副作用；`deliver` 是唯一会"打扰人"的入口。

### 6 夜间链编排

```
run_stages([extract, distill2, rotate]) -> {rc, gaps[]}
```

约束：任一 stage 失败 → 记录 `gaps`，**不重跑**，返回非 0。

### 7 索引重建

```
rebuild(experience_body) -> {index, question_bank}   # 不含分数
```

约束：输出的题库**不得带置信度字段**（防光环效应）。

### 8 判定客户端

```
judge(snippet, rubric) -> {class, severity, anchor, reason}
```

约束：独立进程/独立调用；输入是原始片段；输出不合格（缺 reason/anchor）判为无效，不得回落成"通过"。

## A.3 换语言/宿主时的等价物

| 本实现角色 | 常见等价物 |
|---|---|
| 会话（带工具面的对话容器） | 任意支持工具调用的 agent 框架的 session |
| 定时任务 | 系统计划任务 / systemd timer / cron |
| 全文检索（FTS5 + 双字切分） | 任意支持 CJK 的检索库；没有就自己写双字切分 |
| 压缩归档 | zstd / gzip / zip 均可 |
| 结构化账本 | JSONL 追加最省事（人也读得懂） |
| 判定（外部模型） | 任意可调用模型；便宜或本地优先 |

**唯一不能随便换的是"文件即接口"这一层形状** —— 换了就等于换了架构，需要重写两个域。

## A.4 什么没有包含在参考实现里

诚实清单：

- **没有**安装器 / 配置向导 / 容器编排。
- **没有**多用户与权限模型（单机单用户假设）。
- **没有** Web UI（面板是可选观测，不是健康结论来源）。
- **没有**评测基准（33 条不变量中 `Q0` 受控量化 **0 条**；机制在跑且有产物，缺的是「不带它会差多少」的数字，见 `07-sources.md` §2 / §5）。

如果你需要上面任何一项，说明你的场景已经越出本白皮书的假设，请把它们当作"另外的设计"而不是"本架构的缺失功能"。
