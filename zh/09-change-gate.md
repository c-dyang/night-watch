# 变更治理 · 从脚本头到准入闸

> 这一卷回答一个问题：**我改了这里，还有哪里没改。**
> 它不解决"这个改动对不对"，只解决"我漏了谁"——而在个人环境里，后者才是事故的常见形状。

- 版本：`v0.1-draft` ｜ 署名：`c-dyang` ｜ 文档许可 CC BY 4.0

---

## 1. 问题的形状：个人环境没有消费链

夜链本质是**文件流转**：有生产方（写 `nightly/<date>.md`）、有消费方（读它生成 `review/<date>.md`）。

企业里这条链是被迫可见的——有别人读你的产物，格式即协议，改错会有人来骂。个人环境里消费方只有自己，**契约的两头是同一个人**，于是没有任何外部压力去枚举"谁在读我"。改动因此有一个不报错的爆炸半径。

两个真实实例（同一失效模式，隔了七周）：

| 时间 | 改动 | 漏了什么 | 症状 |
|---|---|---|---|
| 2026-09-09 | 改 `memory_fts_index.py` 的 stdout 格式 | `fragment_search.py` 的两个解析缺陷 | 检索结果字段错位 |
| 2026-10-30 | 给 nightly 骨架行加 `⟨seq N⟩` 前缀 | `nightly_review.py:113` 的 `^(?:\[HH:MM\])?\[(用户\|助手)\]` 锚在 `^` | 命中 199/228/224 → **0/0/0**，review 只剩 webhook 日志，**对话失聪一天**，到次日 22:4x 才由人眼看出文件只有 876 B |

失效模式的共同特征：**只验新增、不验存量**，且**静默归零**——不报错，只是命中数变 0。全黑会当场暴露，这种反而能活一整天。

## 2. 第一版为什么错：把"提示"做成了"契约"

第一版给每个脚本加 `format: <token> | <regex>`，用格式锚在全库交叉验证消费者。跑一次就撞三个语义陷阱：

1. **语义歧义**：`format` 指的是"我产出的格式"还是"我依赖的格式"？
2. **占位符失控**：`-` 表示"无产出"，按字面量粗扫会匹配一切。
3. **上游天然命中**：生产者天生会写出下游的格式 token，方向却是反的，必须豁免祖先，否则每条链都报假阳性。

三个都能修，但代价是**告警里必须长期保持零假阳性**——一旦开始误报，人就会学会忽略它，这套东西就死了。所以结论是反向的：

> **契约没被要求，被要求的是"还有谁"。** 去掉格式字段，改问"谁读我写的路径"，三个陷阱同时消失。

## 3. 定稿：只写地址的五个字段

```python
# [MANIFEST v1]
# id:        nwfcmpxt
# script:    scripts/nightly/distill_extract.py
# reads:     ~/.dsh/sessions/<ws>/session*.jsonl.zstd ; .../distill_watermark.json
# writes:    qq-personal-assistant/nightly/<date>.md
# downstream:vswzou5g
# [/MANIFEST v1]
```

四条铁律：

- **下游引用 `id`，绝不引用路径** —— 让脚本改名 / 挪目录不破坏图。这是整套设计的支点。
- **一行一值，禁内联注释、禁续行** —— 曾经在字段值里写了个 `←` 说明，直接产出 3 条悬挂引用。
- **header 只放地址，不放"这脚本干什么"** —— 描述写 docstring。功能信息本来就在地址里（它读写哪些文件）。
- **块标记带版本** `[MANIFEST v1]` —— 不带的旧正则匹配不到，工具会静默空转。

## 4. 身份：出生点逻辑

`id` 不是随机串，也不是内容指纹，而是**首次登记时它站在哪**的派生值：

```
id = base32_lower(sha1(norm(首次登记路径)))[:8]
```

三段职责必须分开，不能混：

| 概念 | 载体 | 会不会变 | 用途 |
|---|---|---|---|
| 出生点 | **`id`** | 永不变 | **身份**（图的键） |
| 现住址 | `script` | 会变 | 定位 + MOVED 检测 |
| 内容指纹 | **不落 header** | 每次改都变 | 完整性校验（属 git / 备份的活） |

**身份必须与内容正交。** 拿 md5 当 id，改一个空格就换身份，图天天断——hash 是内容指纹，不是身份。

选派生值而不是随机串，是为了**可重放**：

- 碰到没牌子的脚本，算 `f(当前路径)` 去比对登记表 → 命中即"它没搬过家、只是牌子丢了" → 补回同一身份。
- 同一路径只可能产出一个 id ⇒ 登记**幂等**，重复登记不长新身份。
- 两条悬空因此都能收敛：**有记录没文件** = DEAD（误删探测，永不自动删）；**有文件没记录** = ORPHAN（算 f 命中就补头）。
- 搬家后 `id` 与路径不再一致，这不是错误，而是"它曾经在哪"的化石——由 MOVED 报警读数。

### 四级认亲证据（重生 / 换代时怎么认）

| 强度 | 证据 | 处置 |
|---|---|---|
| 1 | 同址：`f(路径)` 相等 | 自动认回 |
| 2 | 功能指纹：`reads`/`writes` 路径集合重合 | 自动建议 |
| 3 | 邻域签名：上下游集合的 Jaccard 重合 | 提示待确认 |
| 4 | basename 撞名 | 仅列出 |
| — | 全不中 | 判**新节点**，老记录 DEAD，**不猜** |

产出重合必然导致邻域重合，反之不然 ⇒ 判据强弱天然是 同址 > 产出 > 邻域 > 名字。**搬家 + 重生 + 改产出路径**三者同时发生时认不出——这是已知盲区，不掩饰。

## 5. 图是涌现的，判定只有四项

不需要中央登记表：`downstream` 引用的就是另一个脚本的 `id`，依赖图自己长出来（等价于每个脚本写一行 `import`）。

| # | 判定 | 类型 |
|---|---|---|
| 1 | 悬挂引用：`downstream` 里的 id 不存在 | 静态 |
| 2 | 链头：无上游入边 | 信息项 |
| 3 | 环：DFS 回边（文件流转成环 = 两条链在互改同一产物） | 静态 |
| 4 | **路径级差集**：`reads` 命中我 `writes` 的脚本 − 我声明的下游 | 静态 |
| 5 | 影响面：改 X 时下游**传递闭包** = 回归清单 | 静态 |

**第 4 项才是真正的探测器**：前四项里只有它能在"我忘了声明"时发出声音。

一个反例也顺手删掉了：原本设"入口白名单"用来判"不可达"，但白名单是第二份真相、必然漂；而图上"不可达"和"链头"同形，硬判必出假阳性 ⇒ 白名单删除，链头由"无入边"零配置得出，漏声明一律交给第 4 项。

## 6. 启动器是链末端，不挂头

`.bat` / `.ps1` 这类启动器**不写 header**，理由是三条叠加的：

1. **编码雷区**：它们是 GBK + 无 BOM + CRLF，且我们头里有 `<date>` 这类尖括号占位，`cmd` 对 `REM` 行的 `%` 一定展开、`<` `>` 有解析风险。
2. **第二份真相**：正文里本来就写着 `"%PY%" ...nightly_archive.py`，再写一遍 `downstream` 就是同一事实存两处，改名时必有一处不更。
3. **它的关系不是数据边**：启动器不产数据、不消费数据，只回答"谁把它拉起来"。

所以改成**正文抽取**：只读非注释行的 `.py` 调用（注释里提到的历史步骤单独列出、不建边），剥离 `%~dp0` / `%VAR%` / `$PSScriptRoot`，方向为 `脚本 → 启动器`（**sink**），`id` 每次现算不落盘——这正是出生点逻辑的正当用法：**因为可重放，所以不必写下来**。

白捡一条报警：**启动器提到但图里没有该节点** ⇒ 改了脚本名、启动器忘了改。

## 7. 准入闸：三道，缺一步不算完成

链路清单只有变成闸门才有强制力。对**生产脚本**的任何修改：

1. **改前闸**：拿 `id` + 回归清单（下游传递闭包）。**影响面 ≥3 或跨链 ⇒ 先告知、分批**。
2. **改后闸**：格式体检通过（ERR / MOVED / DEAD / DUPLICATE 全无）**且**差集为空——出现"有人读我产出但没声明"就先补边，不许放过。
3. **验证闸**：`py_compile` **+ 实跑**；改了产出格式 / 行首锚的，**必须用真实历史文件回放**，命中数**不得从 N 变 0**。

判据一句话：**能自动跑的验证，不许用"我看了一遍"代替。** 影响面本身也是风险数字——1 个下游直接改，≥3 个先说话。

## 8. 真实产出：三条靠差集才浮出来的边

挂完链内 15 个节点后，判定器自己抓出三条**此前无人记得**的依赖：

| 边 | 内容 | 为什么没人记得 |
|---|---|---|
| `nightly_archive → session_bridge` | 归档时把 `review-<date>.md` 一并搬走，而 `session_bridge` 读归档回落路径 | 跨了"归档"与"注入"两个阶段 |
| `pending_archive_nightly → memory_fts_index` | 前者写 `USER.md`，后者索引 `USER.md` | 改画像格式必须重建索引 |
| `external_audit → experience_index` | 前者写 `pending_verdicts.json`，后者读它并应用判定 | **判定器独立复现了 `.bat` 注释里写的 ③→④ 顺序** |

第三条最有说服力：图只从读写路径推出来，却和人工注释里的链序一致。**这说明工具在校验代码，不是在复述我的记忆。**

## 9. 边界（写死在这，免得以后当 bug 修）

1. **约定级依赖不可见**：消费方读的是"行首前缀 / 编号约定"而非文件（`resolve_seq` 读归档，不读 `nightly/`）→ 路径上无交集，只能手工补边。
2. **叶子节点认亲弱**：没有 `writes` 的脚本，结构指纹只剩上游，多个同上游时分不开。
3. **图永不自己完备**：机器只保证"你写下的边自洽"+ 按路径补一部分漏，剩下的靠人补。它的价值是**把清单变活**，不是**把清单变全**。
4. **表是派生物**：快照与图都能从 header 全量重建，表不许携带独有信息。
5. **动态路径会漏**：`os.path.join` 拼出非常规名字时路径匹配失效；要严就得进运行时观测，成本翻倍。

## 10. 与本卷相关的不变量

- **[INV-X6]** 声明与事实必须双向对账 —— 单向自述的清单永远不完整，且失效是静默的。
- **[INV-X7]** 身份与内容正交，且身份必须可重放 —— 否则误删 / 漏挂 / 搬家三类悬空都只能人工。
- **[INV-E7]** 变更准入闸的输入（影响面）与验证必须机械产出 —— 人确认过意图，确认不了清单。

> 一句话收束：**企业用流程把"忘了"变成"提交不了"，个人只能把"忘了"变成"下一次就知道"。**
> 前者靠 OA，后者靠一张每次都能重算的图。
