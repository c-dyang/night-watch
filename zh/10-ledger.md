# 事务台账（已实现）· The Ledger (implemented)

> 前九卷讲的是**为什么要这样搭**；这一卷是全书第一个**已经跑起来、并且有机器断言**的模块。
> 它不是一个新架构，是前面那些不变量在「事件 → 到点提醒 → 受控执行」这一小段上的**落地切片**。
>
> 定位：**检测宽、执行窄、留痕短。** 推理可以很长，留痕必须极短。

- 版本：`v0.1-draft` ｜ 署名：`c-dyang` ｜ 文档许可 CC BY 4.0 ｜ 代码许可 MIT
- 体量：19 个脚本 / 8 份 JSON 契约 / **45 条机器断言** / 3 个出口（即时提醒 · 晨报 · 日历与待办）

## 0. 为什么值得单开一卷

前九卷的证据强度集中在 `Q1`（有产物、无对照），原因是**大多数机制没法做对照**：毁掉一次记忆链、造一个坏分类器，代价都是真的。

台账这一块不一样。它的核心是**几个纯函数**（抽取归一、指纹、判定、派生），于是第一次出现了可以真正消融的东西：

| 这一卷能给的 | 前九卷给不了的 |
|---|---|
| 把一条规则从代码里拿掉，断言立刻红，可复现 | 只能事后回顾事故 |
| 同一份输入、两种实现，输出差异是固定的数字 | 只能描述现象 |
| 45 条断言里每一条都指着某句"不许"，不是指着某个"建议" | 纪律写在文档里，靠自觉 |

所以这一卷的写法也不同：**先给断言，再给道理。** 每条主张后面挂的是脚本与夹具，不是引文。

## 1. 内核：一句话与三条边界

> **不持久化模型未经验证的理解，只持久化可追溯的事实与经验；不限制任务范围，只约束实际行为和效应的边界。**

三条边界，都是"不许"：

| # | 不许 | 为什么 |
|---|---|---|
| ① | 不许持久化"模型的理解" | 理解会漂移，且漂移时**不报错**（[INV-X5]） |
| ② | 不许让判定权与执行权落在同一侧 | 同侧自审必为既有选择辩护（[INV-E1]） |
| ③ | 不许让"判得松"的一侧拥有手 | 宽表敢宽，是因为它只能提示（本卷 I9） |

第 ③ 条是本卷相对前九卷**真正新增**的边界，来历见 §5。

## 2. 链路：一次事件的一生

```
外部源（四类）                      ← 全都能是"可识别事件源"
   │  复制热键 / 手机截图(OCR 后) / 分享 / 录音转写
   ▼
收件箱（单一汇聚点）
   │  按文件名水位去重
   ▼
抽取（纯函数）                      ← 剥信封、归一化、判类型、取时间锚
   │
   ▼
指纹 tkey（字段指纹，不含时间桶与可回滚性）
   │
   ▼
闸门 gate（纯函数：五问 → 2×2 → level，且 level ≤ cap）
   │
   ├─ drop ──────────────► 只留起飞行，不打扰
   │
   ├─ push ──────────────► 到点提醒（见 §4 三通道）
   │                        └─ 有锚 → 建票；无锚 → 永不提醒
   │
   └─ execute ───────────► 派生落地单（准入 + 验收）→ 受控执行体 → 记录
                             └─ 执行权只在这里，且需要人签过字
```

图源：[`../figures/fig6-ledger-loop.mmd`](../figures/fig6-ledger-loop.mmd)

**关键在中间的"漏斗"不在两端的"入口"**：入口可以无限加（I8：检测侧随便加），漏斗的宽度由 `cap` 决定，而 `cap` 只由一个字决定 —— **有没有人签过字**。

## 3. 三入口与硬上限

同类系统最常见的失败是"入口不分"，于是"我发现的"最后变成了"我要求做的"。这里把入口写死成三种，每种一个**硬编码**上限：

| 入口 | 含义 | 上限 | 能不能执行 |
|---|---|---|---|
| `request` | 我要求你做的 | `execute` | 能（仍需指导库签字，见 §5 I1） |
| `record` | 我要求你记的 | `push` | **永不**；要执行必须**新建一条 `request`** |
| `found` | 我发现的 | `push` | 同上 |

> **不变量 I2**：`level ≤ cap`。`cap = min(入口上限, 指导库上限)`。
> 破法只有一个：让模型来填 `level`。所以 `level` 由一个纯函数算，输入里没有模型的意见。

**为什么 `record` 永不能就地升级**：因为"记下来的事"和"我决定要做的事"是两种意图。允许就地升级，等于允许系统把"记录"悄悄转成"承诺"。这条只靠一个整数表达，但它是整套东西里最便宜的一道闸。

## 4. 五问、2×2与三个出口

### 4.1 五问

判定不看"重要不重要"（判不了，[INV-E3]），只问五个能不能被回答的问题：

| 问 | 读什么 | 缺了怎么办 |
|---|---|---|
| 是哪一类？ | 抽取类型 | 判不出 ⇒ `misc`，不建票 |
| 时间点？ | 时间锚 | 无锚 ⇒ 永不提醒 |
| 可回滚？ | 抽取标记 | 不可回滚 ⇒ 不进自动档 |
| 能做？ | `action_id` + 依据档 | 缺动作 ⇒ 只提示 |
| 该做？ | 红线 + 预算 | 出界 ⇒ `drop` 且不再问人（I7） |

**判不了的不许猜**：五问里任何一问答不上来就走保守分支，而不是走"看起来更像的那个"。这条在夹具里有专门的反例（断言：`derivable = true` 但落地单为空 ⇒ 红）。

### 4.2 三个出口，九个时间点

| 出口 | 触发 | 上限 | 形态 |
|---|---|---|---|
| **即时** | 起飞卡上的三个时间点到点（准备 / 时间锚 / 后墙） | 1 条/次，6 条/日 | 一条，≤40 字，必带"为什么现在说" |
| **简报** | 每天一次的既有晨间任务 | 3 行 | 每行 ≤25 字 |
| **日历 / 待办** | 落点分界：与他人的约定 / 自己的截止 | — | 带闹钟的事件 / 带期限的待办 |

三个出口共用一套刹车：

| 刹车 | 作用 |
|---|---|
| 时间点去重（票 × 点） | 同一时刻不重复推 |
| 衰减阶梯（提 1 次降形态 → 2 次进周报 → 3 次沉默） | 同一件事反复没反应就闭嘴 |
| **后墙**：到期当天必现一次，不看衰减 | 唯一能压过衰减的规则 |
| 逾期 7 天归档 | 给"没人管的事"一个体面的退场 |
| **禁止推送清单** | 上限是硬编码的常量，不是配置项 |

> **禁止清单**这一条看着小，其实很关键：一旦允许"把待办列表推给他"，前面所有上限都会以"只是多给一点信息"的名义被突破。

### 4.3 提醒不是主动打扰

事件到达**不推送**，只落票。推不推由时间点算，而这个算法是纯函数：

```
候选点 = { 到期时间 − 提前量, 明确的时间锚, 到期时间（后墙） }
到点且未推过 → 推一条
```

`到点` 是减法的结果，不是"每隔 N 分钟扫一次"的副产品。所以**平静期真的零成本**（[INV-D5]）。

## 5. 本卷的九条内部不变量（I1–I9）

这九条是模块内部的，语义上都能对上全书编号；编号两套并存是为了**改模块时不必动全书**。

| # | 不变量 | 对应 | 破法 |
|---|---|---|---|
| I1 | `binding = null` ⇒ `cap = push`，永不到 `execute` | [INV-E1] | 手动改 cap |
| I2 | `level ≤ cap`，绝不越顶 | [INV-E6] | 让模型填 level |
| I3 | `level = execute` ⇒ `derivable = true` | [INV-E7] | 先执行后补派生 |
| I4 | 落地单的槽位来源 ∈ {原始, 指导库, 常量} | [INV-E4] | 加一个"模型"来源 |
| I5 | 落地单只由生成函数写（带常量签名） | [INV-X1] | 脚本手写一行 |
| I6 | 起飞行只增不改 | [INV-X3] | 就地 UPDATE 一行 |
| I7 | 出红线 ⇒ `drop` 且**不问人** | [INV-E3] | 把红线做进提示词 |
| I8 | 检测侧随便加；执行侧改动必须一次人点头 | [INV-E7] | 顺手放宽 cap |
| **I9** | **宽表无执行权**：降档判定的出口只能是提示层 | **候选 [INV-X8]** | 给宽表接一个执行动作 |

### I9 的来历（这是本卷最值得记的一条）

为了不在切换时丢功能，这里保留了一条**宽松的旧通路**：严表判不了的条目，退回一张"填表式"的宽表去处理（提取字段 → 写日历 / 挂提醒）。

问题本来是：**两张表并存，会不会双判？**

答案不会，因为顺序固定 —— 先严后宽，严表接得住就不退回。但更关键的判断是**为什么宽表可以宽**：

> 宽表的出口只有两个：写日历、挂提醒。都是幂等提示动作，错了删掉即可。
> 而执行权（真正动手）只存在于严表那条链，且需要人签过字。

所以这不是"两个判定器谁更可靠"，而是**判定精度与效应权限解耦**：宽表敢松，是因为**它没有手**。它判错的代价是"多一条提醒"，严表判错的代价是"多一次真实执行" —— 差一个数量级。

**这条论证有一个前提，必须写明**：宽表的安全性不来自严表的护栏，而来自宽表自己的动作边界。**一旦宽表的出口变成"能做一件事"，它就必须用同一张严表。** 所以 I9 不是"宽表永远安全"，而是"宽表的出口必须永远是提示"。

## 6. 证据：两处真消融 + 一次批量升级

### 6.1 消融一：指纹里放不放"时间桶"

同一件事在不同时间发生，该不该算同一件？

把时间桶（早/午/晚）与可回滚性放进指纹时，夹具发生的是这个：

| 配置 | 20 例样本 | 分组结果 |
|---|---|---|
| 时间桶 + 可回滚性 **进** 指纹 | 20 例 | 同一语义类被切成多个 tkey，断言红 |
| 两者 **不进** 指纹（+ 媒体类忽略对象） | 20 例 | **收敛为 7 组 / 7 个 tkey** |

**结论**：指纹只认"是什么 + 对谁"，不认"什么时候"与"能不能撤"。后两者是**发生属性**，不是**身份属性**。放进身份 ⇒ 同一件事每次发生都成了新事，经验永远攒不起来。

这是一次可复现的消融：改两个字段，跑同一批样本，输出从"红"变"绿"，分组数从分散收敛到 7。

### 6.2 消融二：自哈希用哪种规范化

护栏文件需要自校验（防"顺手改宽"）。第一版把自身字段 `pop` 掉再算摘要，第二版把它**归零**再算。同一份文件：

| 规范化方式 | 算出的摘要 | 与文件内记录是否一致 |
|---|---|---|
| `pop` 掉自身字段 | `aa2f074c41dc826f` | 否（**永不自洽**） |
| 归零后计算 | `0328c3f6c9a42dde` | 是 |

两种写法生成的是两个不同的 JSON 串，所以摘要必然不同 —— **自指字段的摘要必须规定唯一一种规范化形态，否则这道校验永远在第一秒就失败，且失败得"很像真出错"**。

这类问题的价值在于：它不是逻辑错，是**两个都合理的写法产生了不同的字节**。没有对比就永远发现不了。

### 6.3 批量升级：一批条目从 `Q2` 升 `Q1`

有机器断言的条目不再依赖"我记得它这么做"，而是**断言红过才算数**。以下条目在实现后可以升到 `Q1`（有产物 + 可复现断言），但**不升 `Q0`** —— 因为还没有"不带它会差多少"的对照（见 `07-sources.md` 的判据与 `06-invariants.md` 变更规则第 3 条）：

| 条目 | 升级理由 |
|---|---|
| [INV-E6] 预检不退化为审批 | 判定函数有 10 条夹具，含"上限不许被越过"的反例 |
| [INV-E7] 准入闸输入机械产出 | 落地单由生成函数写、签名是常量，脚本手写一行即断言红 |
| [INV-D5] 唤醒而非轮询 | 提醒由"到点减法"触发，平静期零调用（可复现） |
| [INV-D8] 判断与投递分离 | 判定只写票，投递只读票，两侧文件级隔离 |
| [INV-X3] 会话是缓存，文件是真相 | 全部状态在追加日志里，进程可随时起停 |
| [INV-X5] 静默失败可与静默成功区分 | 无产物 ⇒ 显式记异常标记；`blocked` 与"崩溃"分开计 |

## 7. 真实跑出来的四个坑

这一节是 `05-appendix-b-pitfalls.md` 的续篇 —— 全部来自本模块上线当天的真实数据。

| 坑 | 现象 | 根因 | 判据 |
|---|---|---|---|
| **① 信封当正文** | 14 条录音转写全部被判成同一类型、塌成同一个指纹 | 文件头是 markdown/YAML 信封（标题 + 元数据 + 小节名），被当成内容喂进抽取 | **先剥信封再抽取**；顺手把信封里的发送者/标签变成结构化字段 |
| **② 指纹算了但没落盘** | 周审永远报"无候选"，看起来像"没有规律" | 指纹只在调试时算，从未写进事件 | 判据：**任何"派生字段"必须随主体落盘**，否则下游永远是空 |
| **③ 自指哈希永不自洽** | 护栏校验在第一天就失败，且很像"文件真被改了" | 见 §6.2 | 自指字段的规范化形态必须唯一且写死 |
| **④ 同日爆发被当成习惯** | 同一天出现 3 次的条目被提成"规律"，建议建规则 | 只看次数不看跨度 | 判据：**必须跨 ≥3 天才算习惯**；同一天多只是一次爆发 |

四个坑的共同点：**都不是逻辑错，都是"看起来对但语义错位"**。所以机器断言在这里的价值不是"防手滑"，是**把语义错误变成可复现的红**。

## 8. 已知限制（不美化）

| # | 限制 | 后果 | 打算 |
|---|---|---|---|
| 1 | **类型识别靠词表** | 新类事件一律落 `misc` ⇒ 不进提醒 | 只能靠周审把高频 `misc` 提炼成规则，慢 |
| 2 | **提前量是常量**（约定 24h / 交付 48h / 事务 72h） | 需要提前一周准备的事只会提前一天说 | 应从历史"收到提醒 → 实际处理"的中位间隔反推 |
| 3 | **票不会自己退场** | 没人关的票靠衰减沉默 + 7 天归档"遗忘退场"，不是"判定退场" | 可接受，但意味着库的清洁度取决于人多久看一次 |
| 4 | **判定器仍偏薄** | 真实批次里全部判 `push`，`drop` 一次没触发 | 缺一条"判不了就不值得提醒"的出口（待改） |
| 5 | **执行分支只验证过"拒绝"** | 真实调用的两次都是 `blocked`（缺源、缺网），`done` 分支未覆盖 | 等第一条真实可执行任务 |

第 5 条尤其要说清：**"能拒绝"不等于"能干活"**。两次真机调用都返回 `blocked` 且理由正确（一次指出目标盘不存在，一次指出 HANDOFF 没给源），这证明了护栏与契约有效，但**"成功完成一次执行"这件事，本卷还不能声称验证过**。

## 9. 复现最小集

不需要宿主、不需要模型，只要有 Python 与文件系统：

| 件 | 数量 | 作用 |
|---|---|---|
| JSON 契约 | 8 | 事件 / 起飞行 / 落地单 / 记录 / 指导库 / 护栏 / 模板 / 判定契约 |
| 纯函数 | 4 | 抽取归一 · 指纹 · 判定 · 派生 |
| 有副作用的 | 3 | 吸纳 · 建票 · 投递 |
| 机器断言 | **45** | 抽取/指纹 20 · 判定 10 · 提醒 7 · 护栏 8 |

跑法（脱敏后）：

```bash
python scripts/collect.py --inbox          # 吸纳（文件名水位去重）
python scripts/extract.py                  # 抽取（纯函数；重复运行不重写）
python scripts/intake.py                   # 判定 → 起飞行 → 够条件才建票
python scripts/due_scan.py --wave W2 --md  # 简报节
python scripts/w1_tick.py --dry-run        # 到点提醒（默认只算不发）
python tests/run_fixtures.py               # 45 条断言
```

**默认全部 dry-run**：执行类脚本必须显式 `--exec` 才动手。这不是谨慎，是 I8 的实现方式 —— 默认值本身就是一道闸。

## 10. 这一卷想留给读者的三句话

1. **把"不许"写成断言，不要写成段落。** 段落会被下一次改动忘掉，断言不会。
2. **判得松的一侧不许有手。** 松和严可以并存，前提是它们的出口不是一个东西。
3. **留痕要极短。** 推理可以很长，但落地到磁盘的必须只有"发生了什么 + 凭什么"，否则库会长成一份自我论述。

> 对应全书立场：会话可以清空，因为记忆不在会话里；模型可以便宜，因为难的部分搬进了结构；
> **而"这件事到底做没做、凭什么能做"，单独用一张台账来管。**
