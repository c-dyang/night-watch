# 设备卷：结果信号、0 成本闸门与逐级处理

> 本卷只回答三个问题：**怎么知道出事了**（信号）、**怎么不为此烧钱**（闸门）、**谁有资格动手**（阶梯）。
> 核心一句话：**一切结果信号都可以唤醒巡检，但唤醒之前必须先过一道不花钱的闸门。**

---

## 1. 一切结果信号

### 1.1 四类信号

| 类 | 具体形态 | 强 | 中 | 弱 |
|---|---|---|---|---|
| **存活** | 心跳行、探针响应、端口可达 | 探针连续 N 次无响应 | 单次无响应 | 进程不在 |
| **结果** | 退出码、任务返回值、执行体自报 | 非 0 退出码 | 无返回 | 返回了但语义模糊 |
| **产物** | 文件的 mtime / 大小 / 内容、记录条数 | 产物缺失或内容为空 | 新鲜度超期 | 文件存在 |
| **调度** | 调度器的上次结果、下次触发时间 | 上次结果异常 | 超期未触发 | 状态显示正常 |

**信号强度决定处理级别**（见 §3）：强信号可以直升 L2/L4，弱信号只进 L0/L1。

### 1.2 三条取值铁律

1. **判活看产物，不看进程** —— 进程在 ≠ 功能在 [INV-D1]。
2. **健康结论只能取自链末端产物** —— 观测点写在中段，就等于只观测了前半段 [INV-D2]。
3. **执行体必须自报结果** —— 任何"退出码不可观测"的执行体（经隐藏窗口启动器、经包装脚本、经远程调用），都必须由自己写一行结果，否则调度器看到的永远是成功 [INV-D3]。

### 1.3 为什么"面板绿"是最危险的状态

面板是**观测者的自我报告**。三种情况都长得一样：

- 真的正常。
- 检查程序自己坏了，输出默认值。
- 检查点在中段，后半段死了。

所以面板只能当**索引**用（"大概正常，去查一下末端产物"），不能当**结论**用。

推论：**静默失败必须能与静默成功区分** [INV-X5] —— 任何只会输出"正常 / 无异常"的观测点都满足不了这一条，因为"没有输出"与"输出正常"在它那里是同一个状态。这条看起来是小细节，实际上是本卷全部设计的起点：**如果面板可信，就不需要闸门与阶梯了。**

## 2. 0 成本闸门

### 2.1 为什么必须先过闸门

数量级关系：

```
信号数 : 异常数 ≈ 100 : 1   （正常时甚至 1000 : 1）
```

如果每个信号都唤醒一次模型判定：

- **成本随噪音涨**，而不是随异常涨；
- **延迟**：模型调用是秒级，而"值不值得看"应该是毫秒级；
- **判定疲劳**：判定被大量"没事"喂饱，真正的异常反而不显眼。

所以闸门的职责不是"判断严重性"，而是**用确定性规则把 99% 的正常信号消耗掉，只让 1% 进入需要算力的环节** [INV-D4]。

### 2.2 闸门里只允许四类判据

| 类 | 形态 | 例子（抽象） |
|---|---|---|
| **新鲜度** | 产物 mtime 与期望周期比较 | 「日报文件最后修改时间 < 今日该产出时间」 |
| **白名单** | 目标/动作是否在允许集合内 | 「该动作属于可自动修复的幂等集合」 |
| **去重** | 指纹 + 时间窗 | 「同一来源同一判据 10 分钟内只唤醒一次」 |
| **已知抑制** | 抑制表命中（带 TTL） | 「该 (单位, 判据) 已被抑制，剩 3 天」 |

四类都是**查表或比较**，没有推测、没有归因、没有语义理解。

### 2.3 闸门的三态输出（不是二态）

| 输出 | 含义 | 后续 |
|---|---|---|
| **drop** | 明确正常（新鲜度达标、白名单外且无需处理） | 只累加计数，不建事件 |
| **defer** | 值得记但不必现在动（弱信号、首次出现、处安静时段） | 进日结，不唤醒 |
| **wake** | 值得花一次判定算力 | 生成唤醒事件（C3）→ 执行域 |

**两态闸门（要不要）一定会错**：要么噪音进模型，要么需要累积观察的信号被丢掉。三态的分界线是「现在动 vs 今天汇总 vs 不用管」。

### 2.4 闸门的两条设计禁忌

| 禁忌 | 为什么 |
|---|---|
| **闸门不得有副作用** | 闸门必须是纯函数：只读信号，只输出三态。一旦它开始"顺手修一下"，误判就直接变成破坏，且不可回溯 |
| **闸门不得写业务逻辑** | 业务规则会漂移，写进闸门就变成"改闸门才能改业务"，闸门不再是基础设施而成了业务代码的垃圾桶 |

### 2.5 误判代价不对称

| 误判 | 代价 | 结论 |
|---|---|---|
| **漏判**（该唤醒未唤醒） | 静默腐烂，几周后发现 | **极高**，且不可见 |
| **误唤醒**（不该唤醒却唤醒） | 多花一次廉价判定 | 很低，且可测 |

推论：**阈值应当偏保守（倾向 wake）**，然后用去噪而不是用"提高门槛"来压噪音。这是本卷最容易做反的一处 —— 人的直觉总是"别烦我"，于是把阈值调到刚好安静，安静下来就等于瞎了。

### 2.6 抑制的粒度与期限

> **抑制粒度必须 ≥ 一个可独立失败的单位，且带 TTL、可回溯。** [INV-D7]

| 抑制粒度 | 后果 |
|---|---|
| 整个"来源" | 一次误报 ⇒ 该来源下所有真实失败一起盲掉整个 TTL |
| **单个「目标 × 判据」** | 只盲掉真正被认为误报的那一条 |
| 单次事件 | 几乎无效（事件指纹每次不同），抑制表会膨胀 |

三条附加要求：**TTL 必填**（无期限抑制 = 永久失明）；**抑制行为本身要留痕**（谁抑制的、理由、到期时间）；**抑制到期必须自动恢复**，而不是等人想起来。

> 实践中最危险的一次决定是：**该不该因为"这次是误报"而抑制整个类别**。答案是几乎永远不该 —— 宁可多容忍一次误报。

## 3. 逐级处理：L0 → L4

### 3.1 阶梯定义

| 级 | 名称 | 谁做 | 成本 | 权限 | 退出条件 |
|---|---|---|---|---|---|
| **L0** | 静默记录 | 执行体 / 探针 | 0 | 只写 | 永远（每级都先过 L0） |
| **L1** | 日结归集 | 夜间链 | 0 | 只投影 | 当日结束 |
| **L2** | 唤醒巡检 | 免费/本地模型判定 | 极低 | 只判不改 | 判定出"值不值得动" |
| **L3** | 白名单自愈 | 幂等动作执行器 | 低 | 限白名单 | 修完必须自验 |
| **L4** | 提级给人 | 队列 + 投递 | 人 | 无 | 人处置或过期重提 |

**每一级都先经过上一级**：没有"直接跳到 L4"的通道，因为跳级会绕过去重与抑制，产生轰炸。

### 3.2 升级条件（必须显式写死）

- 同一 `(目标, 判据)` 在窗口内出现 **N 次** ⇒ L2。
- 强信号（产物缺失、非 0 退出码）⇒ 直接 L2，不等累积。
- L2 判定"值得动"且动作在白名单 ⇒ L3。
- L3 自验失败 / 动作不在白名单 / 涉及凭据与安全面 ⇒ L4。
- L4 超过时限未处置 ⇒ 重提（本轮重提，不是无限循环）。

### 3.3 L3 的准入：只有幂等动作

> **能自动修的只有幂等动作，其余一律提级。** [INV-D6]

幂等的定义要写死：**执行两次与执行一次，结果一致，且副作用不累积。**

| 动作 | 幂等 | 可自愈 |
|---|---|---|
| 重启一个无状态服务 | 是（重启两次仍是"已重启"） | 可 |
| 补写一行缺失记录 | 是（按主键 upsert） | 可 |
| 改配置文件 | **否**（两次可能叠加、覆盖人工修改） | 不可 |
| 删除文件/回滚数据 | **否** | 绝对不可 |
| 发消息通知人 | **否**（会重复发） | 不是自愈动作，是投递动作 |

**自愈必须自验**：修完再看一次产物；验证失败按"未修复"处理并升级，而不是按"已尝试"关掉。

### 3.4 判断与投递分离

> **执行者只写队列；投递由有记忆的一侧负责。** [INV-D8]

| 角色 | 职责 | 原因 |
|---|---|---|
| 判定方（L2） | 判定 + 写一条队列记录 | 它没有记忆，不知道"今天已经打扰过几次" |
| 执行者（L3） | 修 + 自验 + 写队列记录 | 同上 |
| 投递方 | 读队列 → 按安静时段、去重、频率上限投递 | **它有记忆**，能决定"该不该现在说" |

三者合一会出现的典型症状：**同一个问题在一小时内被报 8 次**，或者在凌晨 3 点打电话。投递侧的规则（安静时段只入队、同类 12 小时内只投一次、每轮最多 3 条）本来就是"记忆"才能做的判断。

### 3.5 去噪三层，不加第四层

```
① 任务级记忆：生产者自己记得"这事我刚报过"
② 抑制表（带 TTL）：被判定为误报/已知的条目不重复唤醒
③ 时间窗去重：同一指纹在窗口内只唤醒一次
```

[INV-D9] 为什么禁止第四层：每加一层都只为解决一个具体误报，但层与层之间会互相掩盖 —— 最后你既不知道一条信号为什么被吞，也不知道该改哪一层。**宁可让某一层变粗，也不再分层。**

### 3.6 辅助会话惰性创建

巡检会话缺席 ≠ 巡检失败 [INV-D10]。

| 现象 | 错误结论 | 正确判据 |
|---|---|---|
| 今天没有巡检会话记录 | "巡检没跑" | 看**产物**（当日 day log / 审计行）是否存在 |
| 会话创建了但没有内容 | "巡检执行了但没发现" | 判据同上看产物，不看会话 |

会话说到底是**注意力容器**，它按需创建；把"容器在不在"当健康指标，等于用面板当结论。

## 4. 最小契约

### 4.1 判据表（一行一个可测断言）

```json
{
  "id": "R-001",
  "target": "<被观测对象：服务 / 任务 / 文件 / 队列>",
  "signal": "liveness | outcome | artefact | scheduler",
  "predicate": "<可测断言，含阈值>",
  "severity": "low | medium | high",
  "evidence": ["<需要记录哪个字段作为证据>"],
  "action_class": "none | readonly | idempotent_whitelist | escalate",
  "ttl_days": 14
}
```

要求：**`predicate` 必须能被脚本判定**（阈值 + 字段），不能是"看起来是否健康"。

### 4.2 上报契约（谁报、报什么）

| 谁 | 报什么 | 形式 |
|---|---|---|
| 执行体（不可被调度器观测的） | 自己的退出码与关键结果 | 一行结构化记录，由**执行体自己**写 |
| 监督方（外部检查器） | "产物是否出现/是否新鲜"的结论 | 一行审计记录，**不得**由被检查任务写 [INV-X1] |
| 调度器 | 上次结果与下次触发时间 | 由调度器自身提供，只作辅助证据 |

### 4.3 唤醒事件（C3）

```json
{
  "signal_id": "<指纹>",
  "rule_id": "R-001",
  "raw": {"<信号原文，不加工>"},
  "gate": {"state": "wake", "reason": "<为什么过闸>", "dedup_age_s": 0},
  "at": "<ISO 时间>"
}
```

要点：`raw` 必须带**未加工的原文**，因为下游判定要自己得出结论，不能吃二手的"看起来是故障"。这是 [INV-E2] 在设备域的对应要求。

### 4.4 三条可测判据

1. **注入式验证**：人为制造一次真实失败（例如让产物不更新），看它是否在预期时间内走到 L2；再让一个白名单动作失败，看它是否走到 L4。**没做过注入测试的巡检，等于没有巡检。**
2. **静默期零成本**：全部正常的一天，模型调用次数应为 **0**（只有闸门在跑）。不为 0 说明闸门失效或判定下沉了。
3. **抑制可回溯**：任取一条抑制记录，能回答"谁、何时、为什么、何时到期"。

## 5. 本卷失效模式（诚实清单）

| 失效 | 症状 | 结构原因 |
|---|---|---|
| 面板绿而链条死 | 一切正常直到某天发现三周没产出 | 观测点在中段 [INV-D2] |
| 调度器永远看到成功 | 失败只在日志里 | 执行体未自报 [INV-D3] |
| 抑制即致盲 | 一次误报换来长期沉默 | 抑制粒度过粗、无 TTL [INV-D7] |
| 自愈越修越坏 | 同一动作执行两次产生叠加 | 非幂等动作进了白名单 [INV-D6] |
| 提级即骚扰 | 同一问题短时间多次通知，或凌晨打扰 | 判断与投递未分离 [INV-D8] |
| 巡检缺席被当故障 | 无会话就触发一次处置 | 用容器当健康指标 [INV-D10] |
| 闸门长成业务系统 | 改业务要改闸门 | 副作用与业务逻辑进了闸门 |
| 阈值调到"刚好安静" | 长期无告警，事后全是有迹可循的漏判 | 用提高门槛代替去噪 [INV-D4] |

## 6. 从零搭最小版本（顺序不能换）

1. **先让执行体自报**：任何"结果不可观测"的执行体，改成自己写一行退出码与关键结果。**没有这一步，后面全部建立在幻觉上** [INV-D3]。
2. 写**三条判据**（一条存活、一条结果、一条产物新鲜度），判据里只有阈值与字段。
3. 写**闸门**：三态输出，纯函数，无副作用；先只实现新鲜度与去重。
4. 写**事件落盘 + 队列**：唤醒事件一条一条追加，队列是给人看的文件。
5. 写**投递侧**：安静时段、同类去重、每轮上限 —— 这三条规则就足够，别做更多。
6. 加 **L3 白名单**：只放一个幂等动作进去，且必须自验。
7. 做**一次注入式验证**：制造失败，看它走完全程。

到第 4 步就能"知道出事了"；第 6 步才谈得上自愈；第 7 步才谈得上可信。**跳过第 7 步的巡检只是心理安慰。**
